# 자기소개서용 문제 해결 사례

한성공학경진대회(EMS 재활 보조 시스템 프로젝트, 팀장 역임) 진행 중 겪은 문제와
해결 과정을 자기소개서/면접에 바로 쓸 수 있도록 상황-과제-행동-결과(STAR) 형식으로
정리했습니다. 원문 대화와 날짜별 상세 기록은 [`프로젝트_진행_타임라인.md`](프로젝트_진행_타임라인.md)에
있습니다.

---

## 1. 하드웨어 2채널 미작동 문제 — 원인을 구조적으로 좁혀나간 디버깅

**상황(Situation)**
EMS 자극 보드에서 2개 채널 중 1개만 정상 동작하고 나머지 1개는 전혀 반응하지
않았습니다. 처음에는 "코드에서 게이트를 잘못 열었나" 하는 의심을 받았습니다.

**과제(Task)**
대회 제출 기한이 얼마 남지 않은 상황에서, 원인이 코드/배선/납땜/부품(소자) 중
무엇인지 팀장으로서 빠르게 좁혀 해결해야 했습니다.

**행동(Action)**
- 먼저 코드를 재검토해 "1번 채널을 여는 로직과 2번 채널을 여는 로직이 동일한데
  1번만 되는 것은 코드 문제로는 설명이 안 된다"는 점을 논리적으로 확인해 코드
  원인 가능성을 낮춰놓고 시작했습니다.
- 배선을 바꿔 꽂아보는 실험(1번선을 2번 구멍에 꽂으면 안 되고, 2번선은 어느
  구멍에 꽂아도 되는 것을 확인)으로 문제를 "보드의 특정 채널 회로"로 좁혔습니다.
- 원인 후보를 (1) 소자 삽입 오류, (2) 납땜 불량, (3) 소자 자체 불량 3가지로
  구조화하고, 예비 부품을 챙겨 전자 수리 업체에 오실로스코프 진단을 의뢰했습니다.
- 진단 과정에서 나온 "호환 보드(가품 아두이노)는 CH340 드라이버와 Old Bootloader
  설정이 필요하다"는 정보까지 팀에 정리해 공유했습니다.
- 최종적으로 배선을 다시 연결하는 것으로 해결했습니다.

**결과(Result)**
대회 제출 전 2채널 모두 정상 동작을 확보했습니다. 이 경험으로 하드웨어 문제를
"코드 vs 배선 vs 부품"처럼 층위를 나눠 하나씩 배제해가며 원인을 좁히는 체계적인
디버깅 방식을 체득했습니다.

## 2. 핵심 센서 고장 → 촉박한 마감 속 대안 설계로 피벗

**상황(Situation)**
예선 제출을 며칠 앞두고, 손동작을 측정하는 데 쓰던 플렉스 센서 장갑을 분해
점검하다가 납땜이 금속 접점이 아닌 곳에 되어 있고 전선이 여러 곳에서 끊어져
있는 것을 발견했습니다. 제출 기한 내 재조달·수리가 불가능한 상황이었습니다.

**과제(Task)**
프로젝트의 핵심 입력 장치가 통째로 못 쓰게 된 상황에서, 팀장으로서 기한을
지킬 수 있는 대체 수단을 즉시 결정해야 했습니다.

**행동(Action)**
- 팀원이 제안한 "카메라(MediaPipe)로 손 모양을 인식하는 방법"을 임시방편으로
  즉시 시도하도록 했습니다.
- 같은 날 안에 프로토타입이 상당 부분 동작하는 것을 확인하고, 하드웨어 고장
  위험이 없고 비용도 더 저렴하다는 장점을 근거로 임시방편이 아니라 정식
  아키텍처로 채택하기로 결정했습니다.
- 기존 EMS 자극 출력 하드웨어(보드, 펌웨어)는 그대로 유지한 채 "목표 동작을
  무엇으로 측정하는가"만 교체하는 최소 변경으로 리스크를 관리했습니다.

**결과(Result)**
예선 제출 기한을 지켰을 뿐 아니라, 결과적으로 센서 배선 단선 위험이 없는 더
안정적인 최종 아키텍처(카메라 비전 기반 폐루프 제어)로 발전시켰습니다. 이후
본선에 진출해 최종적으로 금상을 수상했습니다.

## 3. 소프트웨어: 원인이 안 보이는 버그를 재현·격리로 추적

**상황(Situation)**
음성 비서 기능("탱글이")을 한 번 사용한 뒤 다시 호출하면 전혀 반응하지 않고,
심할 때는 모드 선택 버튼 자체가 눌리지 않는 문제가 있었습니다.

**과제(Task)**
증상이 "가끔, 조작 순서에 따라" 발생해 재현 조건을 특정하기 어려운 버그를
찾아 고쳐야 했습니다.

**행동(Action)**
- 마이크가 죽었을 때 계속 재시작을 시도하는 감시(watchdog) 로직을 추가해 1차
  증상(재호출 무반응)을 완화했습니다.
- 더 심각한 증상(버튼 자체가 안 눌림)은 콘솔 에러를 추적해 "마이크 자동 시작
  코드가 아직 선언되지 않은 변수를 참조해 스크립트 전체가 멈추는" 초기화 순서
  문제(TDZ)임을 특정했습니다.
- 변수 선언 위치를 파일 최상단으로 옮겨 근본 원인을 제거했습니다.

**결과(Result)**
음성 비서 기능이 세션 중간에 끊겨도 스스로 복구되고, 다른 UI 기능에 영향을
주지 않도록 안정화했습니다. 증상만 임시로 덮지 않고 재현 조건을 좁혀 근본
원인을 찾는 디버깅 습관을 확인한 사례입니다.
